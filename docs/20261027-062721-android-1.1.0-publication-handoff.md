## 3. 1.1.0 功能范围

1.1.0 在原有 HTTPS 多主机管理、扫码绑定和长期设备令牌之外，新增 go-nx 低带宽远控：

- 固定 sidecar 证书指纹的扫码配对；
- 64x64 tile 差分画面查看；
- 触摸、滚轮、键盘和 Unicode 输入；
- 显式连接状态机、20 秒前端超时和分类恢复动作；
- 后台、断线和 Activity 销毁时释放鼠标/滚轮/按键状态；
- 旧连接回调隔离，避免旧错误覆盖新连接；
- 成功连接后才持久化屏幕尺寸。

这是面向静态桌面和轻量交互的低带宽 tile 数据面，不是 H.264/HEVC/AV1 视频串流，也不包含音频、剪贴板、文件传输或多显示器切换。

## 5. Android 如何发现更新

客户端更新机制位于 `Updates`、`UpdateWorker` 和 `MainActivity`：

- App 启动时安排周期任务并立即触发一次检查；
- WorkManager 约每 6 小时检查一次，要求联网；
- 用户也可点击“现在检查更新”；
- 只有清单 versionCode 高于已安装版本时才下载；
- 下载后校验包名、versionCode、versionName、minSdk、大小、SHA-256 和签名；
- 校验通过后调用 Android 系统安装器，由用户确认安装。

因此，“推送更新”在这里表示更新源已切换并可由客户端发现，不代表 FCM 消息已送达，也不代表设备会自动静默升级。

## 6. 回滚方法

首选保留 `nightdesk-7.apk` 并发布修复后的更高 versionCode。若必须撤回更新源，可以原子恢复发布前清单：

```bash
ssh AI
cd /home/tony/dev/nightdesk-update-feed
cp -p manifest.json "manifest.json.pre-rollback-$(date +%Y%m%d-%H%M%S)"
cp manifest.json.bak-20261027-062447 .manifest.json.rollback
mv .manifest.json.rollback manifest.json
curl -fsS http://127.0.0.1:17768/healthz
curl -fsS http://127.0.0.1:17768/api/v1/android-update
```

要求：

- **不要删除 `nightdesk-7.apk`**，它是回滚、审计和再次发布的证据；
- 恢复旧清单后，新下载者会重新得到 1.0.4；
- Android 客户端不会接受 versionCode 降级，已经安装 1.1.0 的设备不会因清单回滚而自动降级；
- 回滚后应再核对健康检查、manifest、`latest.apk` 的 HTTP 状态、长度和 SHA-256；
- 不要手工编辑正在使用的 manifest；必须写临时文件后同目录原子 `mv`。
